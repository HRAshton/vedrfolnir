# Vedrfolnir 0.3.0rc1 — proposed candidate notes

**Unreleased.** The planned tag is `v0.3.0rc1`; this recreated repository has
no published releases yet. Historical v0.2.0 publication refers to the old
repository. This PR defines a contract; it creates no release/tag/PyPI/GHCR
publication. See the [release contract](../release-contract.md).

## Candidate changes since the historical preview

- Job-level monitoring and API additions, improved source ingestion and
  recorded October 2026 experiments are present in the source baseline.
- `vedrfolnir doctor` and `vedrfolnir serve` provide local configuration
  checks and single-worker serving; CSV and optional SQL Server fixtures
  provide source-build walkthroughs and read-only mounts.
- Known placeholder admin tokens and unknown newer SQLite schemas are
  rejected. Legacy pool columns use an additive schema-v1 migration;
  shutdown waits for the polling thread before disposing storage.
- The authoritative `__version__` is now `0.3.0rc1`; package metadata and
  API version derive from it rather than independently declaring a final version.
- Hosted CI validates stable Python 3.15, real River, clean wheel/sdist
  installs, commit policy, shell scripts and workflows. Protected-tag
  PyPI/GHCR publishing remains a subsequent milestone. Local validation
  remains available; heavyweight benchmarks remain opt-in.

## Planned distribution and support

CPython 3.15 only; initial official container target **Linux/amd64**,
`ghcr.io/hrashton/vedrfolnir:v0.3.0rc1`, identified canonically by its digest.
The planned wheel is `vedrfolnir-0.3.0rc1-py3-none-any.whl` and sdist is
`vedrfolnir-0.3.0rc1.tar.gz`. Checksums, container SBOM and release notes
follow the names in the release contract. PyPI ownership is unverified;
these names do not imply downloadable artifacts exist.

The official image will support demo/CSV and omit the optional MSSQL driver.
SQL Server requires a source build with the extra and separate integration
validation; no verified MSSQL image is promised. Current Compose builds
locally. Future consumer Compose must pull an immutable version/digest.

Use one host, one app instance and one worker per persistent SQLite database.
Back up before upgrades and verify restoration; do not mix source histories.
Read API/UI endpoints are unauthenticated: keep localhost binding and require
an authenticating TLS proxy for remote access. Admin tokens protect sync only.
Real-scheduler accuracy, SQL Server compatibility, non-Linux pip installs,
arm64 images and high availability remain unqualified. RCs never move `latest`.

## Before publishing

Run `bash scripts/local_check.sh full` with Python 3.15 and real River,
qualify wheel/sdist installs and the pulled image's demo/CSV persistence smoke,
review security, schema/rollback and accuracy evidence, then authorize an
immutable protected release tag and approved publishing environment.
Repository protections, artifact publication and provenance are subsequent
milestones. Record actual source SHA, commands/tool versions, hashes and image
digest in these notes when qualification is complete. No release from PR contexts.
